# v41 — перевірка потоку перед Android-плеєром

У v40 тайм-аут, помилка або зупинка буферизації могли завершувати підготовку успішно. Плеєр отримував непідготовлений потік; після зовнішнього запуску плагін не мав підтвердження відтворення і не міг безпечно перемкнути реліз.

## Зміни

- Очікування списку файлів: 12 секунд замість 20 на кандидата. Це не загальний ліміт пошуку: декілька послідовних спроб можуть тривати довше.
- Тайм-аут буфера (12 секунд), зупинка його зростання та помилка статусу більше не запускають плеєр. Плагін переходить до наступного кандидата; помилки сервера з ознакою terminal зупиняють підбір.
- Перед запуском перевіряється надходження байтів саме обраного файла за його stream URL та індексом. Перевірка обов'язкова також із вимкненою додатковою буферизацією.
- Запит Range 0–65535; після першої порції даних запит переривається. Для старих WebView, де CORS відхиляє Range, дозволено одну спробу звичайного GET із тим самим загальним лімітом 8 секунд. Вона теж переривається після отримання даних.
- HTTP-помилки, порожні відповіді, HTML/JSON/XML/плейлисти не вважаються відеопотоком.
- Скасування прибирає запити й таймери. Запізнілі callbacks не запускають плеєр.
- Відмова підготовки зберігає сезон, номер серії та позицію для автоматичної наступної спроби.
- Окремий етап «Перевіряю надходження відеоданих…» та причина «Готовність відеопотоку» в діагностиці.
- Правила мови, оцінювання якості та сумісності з v40 збережено.

## Перевірки

173 автоматичні тести, включно з JSDOM UI, відмовами потоку, скасуванням, CORS fallback, автентифікацією, дедлайнами та перенесенням серії. Перевірки синтаксису Node, ES5 (Acorn) та git diff --check пройдені.

Звірено реалізацію stream/Range/CORS у вихідному коді YouROK/TorrServer. Модель конкретного телевізора, його версію TorrServe та реальне декодування фізично не перевірено.

## Межі

Надходження байтів не доводить підтримку кодека, правильність мітки аудіодоріжки чи стабільність усього перегляду. Зовнішній Android-плеєр у цій конфігурації не підтверджує плагіну відтворення та вибрану доріжку. Коротший дедлайн може відсіяти повільну, але живу роздачу; плагін спробує наступну. Перевірка початку файла також не гарантує готовність даних біля збереженої позиції відновлення.
